Public or private?Public ou privé ?
Every repository you create can be private (only you — and people you invite — can see it) or public (anyone can read the code). In this class we create a private repository: your Vercel website stays publicly visible either way, but your code history stays yours. You can flip the switch later in the repository's Settings. Chaque dépôt que vous créez peut être privé (visible uniquement par vous — et les personnes invitées) ou public (lisible par tout le monde). Dans ce cours, nous créons un dépôt privé : votre site Vercel reste publiquement visible dans les deux cas, mais votre historique de code reste à vous. Vous pourrez changer cela plus tard dans les Settings du dépôt.

What just happened — in three wordsCe qui vient de se passer — en trois mots
commit = a labelled snapshot of the folder. repository = the folder plus its whole snapshot history. push = copy the snapshots up to GitHub. The agent runs these; you only need the words. commit = un instantané étiqueté du dossier. dépôt (repository) = le dossier plus tout son historique d'instantanés. push (poussée) = copier les instantanés vers GitHub. L'agent les exécute ; vous n'avez besoin que des mots.

4 · Go live with VercelMise en ligne avec Vercel

Vercel watches your GitHub repository and publishes it to a real URL. You connect it once — every future push then updates the live site automatically, about a minute later. Vercel surveille votre dépôt GitHub et le publie sur une véritable adresse. Vous le connectez une seule fois — chaque poussée future met alors le site à jour automatiquement, environ une minute plus tard.

Habits worth keeping for real workDes habitudes à garder pour le vrai travail
Push at the end of every working session — a push is a free backup. Write commit messages your future self will understand (“add 2024 MDA coverage chart”, not “updates”). And keep anything you wouldn't publish — passwords, personal data, unpublished data — out of the folder entirely; history remembers everything, even deleted files. Poussez à la fin de chaque session de travail — une poussée est une sauvegarde gratuite. Écrivez des messages de commit que votre futur vous comprendra (« add 2024 MDA coverage chart », pas « updates »). Et gardez hors du dossier tout ce que vous ne publieriez pas — mots de passe, données personnelles, données non publiées ; l'historique se souvient de tout, même des fichiers supprimés.

Troubleshooting & FAQDépannage & FAQ

“command not found” / “is not recognized” right after installing« command not found » / « n'est pas reconnu » juste après l'installation
Always a PATH refresh: close every terminal window and open a brand-new one, then retry. Installed tools are only visible to windows opened after the install. Toujours un problème de rafraîchissement du PATH : fermez toutes les fenêtres de terminal et rouvrez-en une nouvelle, puis réessayez. Les outils installés ne sont visibles que pour les fenêtres ouvertes après l'installation.
gh auth login: the browser didn't open, or the code failedgh auth login : le navigateur ne s'est pas ouvert, ou le code a échoué
Copy the URL the terminal prints and open it by hand — the one-time code still works. If the code expired, just run gh auth login again. Check the result any time with gh auth status. Copiez l'adresse affichée dans le terminal et ouvrez-la à la main — le code à usage unique fonctionne toujours. Si le code a expiré, relancez simplement gh auth login. Vérifiez le résultat à tout moment avec gh auth status.
Push fails with “Permission denied” or “Authentication failed”La poussée échoue avec « Permission denied » ou « Authentication failed »
Nine times out of ten the sign-in from Part 2 was skipped or expired. Run gh auth status; if you're not logged in, run gh auth login again and answer Yes to “Authenticate Git with your GitHub credentials?”. Or tell the agent: “my push failed with an auth error — fix my GitHub login.” Neuf fois sur dix, la connexion de la partie 2 a été sautée ou a expiré. Exécutez gh auth status ; si vous n'êtes pas connecté, relancez gh auth login et répondez Yes à « Authenticate Git with your GitHub credentials? ». Ou dites à l'agent : « ma poussée a échoué avec une erreur d'authentification — répare ma connexion GitHub. »
The Vercel deploy failedLe déploiement Vercel a échoué
Open the project in Vercel → Deployments → click the failed one to read the log. For a plain static site the common cause is pushing a folder with no index.html at its root. If the log is cryptic, paste it to the agent: “here's my Vercel deploy log — what's wrong?” Ouvrez le projet dans Vercel → Deployments → cliquez sur celui qui a échoué pour lire le journal. Pour un site statique simple, la cause fréquente est un dossier sans index.html à sa racine. Si le journal est obscur, collez-le à l'agent : « voici mon journal de déploiement Vercel — quel est le problème ? »
I pushed, but the live site didn't changeJ'ai poussé, mais le site en ligne n'a pas changé
Three checks, in order: (1) confirm the push actually happened — git log shows your commit and GitHub.com shows it too; (2) look at Vercel Deployments — a new one should appear within seconds of the push; (3) hard-refresh the browser (Ctrl+Shift+R / ⌘+Shift+R) to skip the cache. Trois vérifications, dans l'ordre : (1) confirmez que la poussée a vraiment eu lieu — git log montre votre commit et GitHub.com aussi ; (2) regardez Deployments dans Vercel — un nouveau doit apparaître quelques secondes après la poussée ; (3) forcez le rafraîchissement du navigateur (Ctrl+Maj+R / ⌘+Maj+R) pour sauter le cache.
Is my code really private? Can I work on sensitive data?Mon code est-il vraiment privé ? Puis-je travailler sur des données sensibles ?
A private repository is readable only by you and people you invite — but your Vercel website is public by design, so anything the site displays is visible to the world. Rule of thumb: code and structure can live in the private repo; put sensitive data behind access controls or keep it out of the deployed folder entirely. Un dépôt privé n'est lisible que par vous et les personnes invitées — mais votre site Vercel est public par nature, donc tout ce que le site affiche est visible par tous. Règle pratique : le code et la structure peuvent vivre dans le dépôt privé ; les données sensibles passent derrière des contrôles d'accès ou restent hors du dossier déployé.
What does this cost if I keep using it?Combien cela coûte-t-il si je continue à l'utiliser ?

GitHub Free : dépôts publics + privés illimités, 0 $. Vercel Hobby : sites personnels non commerciaux, 0 $.
